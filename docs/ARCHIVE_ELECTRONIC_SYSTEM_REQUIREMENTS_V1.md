## 1. وصف النظام

نظام الأرشفة الإلكترونية هو موقع ويب مؤسسي لإدارة الوثائق والملفات والسجلات من لحظة الاستلام أو الرفع، مرورًا بالتصنيف والفهرسة والمراجعة والاعتماد، وانتهاءً بالحفظ طويل الأجل والبحث والاسترجاع والتقارير.  
الواجهة الرئيسية يجب أن تخدم الاستخدام اليومي للمستخدمين، أما الحوكمة والتكامل وجاهزية Staging/Production فتكون داخل صفحة فرعية في الإدارة.

المسار التشغيلي للوثيقة:

```text
وثيقة → تصنيف → بيانات وصفية → رفع/حفظ → مراجعة → اعتماد → بحث واسترجاع → تقارير → حفظ طويل الأجل
```

## 2. أهداف النظام

| الهدف | الوصف |

| تسريع الوصول | بحث سريع ومتقدم وذكي داخل البيانات والملفات. |
| ضبط الصلاحيات | منع الوصول غير المصرح به، خاصة للوثائق المقيدة أو السرية. |
| تقليل الورق | تحويل مسارات الأرشفة إلى إجراءات رقمية قابلة للتتبع. |
| حفظ الأدلة | حماية الملفات الأصلية والـHash وسجل التعديلات. |
| دعم القرار | لوحات متابعة وتقارير إدارية وتشغيلية. |
| حماية البيانات | أمان، نسخ احتياطي، استرجاع، وسجلات تدقيق. |
| التكامل المستقبلي | قابلية الربط المضبوط مع PalWakf وأنظمته دون كسر السيادة أو RBAC. |

## 4. الوحدات الرئيسية في الموقع

### 4.1 الصفحة الرئيسية التشغيلية

يجب أن تكون صفحة استخدام يومي لا صفحة حوكمة. تحتوي على:

- بحث سريع ظاهر.
- إجراءات سريعة: إضافة وثيقة، رفع ملف، مراجعاتي، البحث المتقدم، التقارير.
- إحصاءات مختصرة: إجمالي الوثائق، قيد المراجعة، المعتمدة، المقيدة، ناقصة البيانات.
- آخر الوثائق المضافة.
- آخر المهام المطلوبة من المستخدم.
- تنبيهات تشغيلية دون عرض تفاصيل حوكمة ثقيلة.

### 4.2 لوحة التحكم اليومية Dashboard

| المؤشر | الوصف |
|---|---|
| إجمالي الوثائق | كل الوثائق المسجلة. |
| وثائق هذا الشهر | الإنتاج الشهري. |
| قيد المراجعة | تحتاج إجراء. |
| ناقصة البيانات | تحتاج استكمال. |
| وثائق مقيدة | وصول محدود. |
| وثائق محفوظة نهائيًا | مكتملة الدورة. |
| أكثر الإدارات نشاطًا | حسب عدد الوثائق. |
| متوسط زمن المراجعة | قياس كفاءة العمل. |

### 4.3 إدارة الوثائق

- إضافة وثيقة جديدة.
- تعديل بيانات الوثيقة.
- رفع نسخة أو أكثر.
- ربط الوثيقة بإدارة وموضوع وملف.
- ربط الوثيقة مستقبلًا بأصل وقفي أو قضية أو موقع.
- إرسال للمراجعة.
- اعتماد، إرجاع، تقييد، حجر، أو حفظ نهائي.
- عرض تاريخ النشاط والملاحظات.

## 5. نموذج تصنيف الوثائق

النموذج الإداري:

```text
المؤسسة
 └── الإدارة
      └── الموضوع
           └── الملف
                └── الوثيقة
                     └── النسخ والتمثيلات
```

النموذج الأرشيفي:

```text
Fonds → Series → File → Item → Representation
```

مثال:

```text
إدارة الأملاك
 └── أراضي الوقف
      └── برك سليمان / أرطاس
           └── ملف التسوية العقارية
                └── قوشان عثماني
                └── شهادة تسجيل أردنية
                └── مخطط مساحة
                └── إيصال ضريبة
```

## 7. آلية رفع الملفات وحفظها

### 7.1 أنواع الملفات المدعومة

| النوع | الامتدادات |
|---|---|
| وثائق | PDF, DOCX, XLSX |
| صور | JPG, PNG, TIFF |
| خرائط | GeoTIFF, PNG, PDF |
| أرشيف مضغوط | ZIP |
| نصوص | TXT, CSV |
| صوت/فيديو — اختياري | MP3, MP4 |

### 7.2 متطلبات الرفع

- Drag & Drop.
- رفع متعدد.
- تحديد نوع الوثيقة قبل أو بعد الرفع.
- منع الملفات الخطرة.
- حد أقصى للحجم حسب السياسة.
- حساب SHA-256 لكل ملف.
- إنشاء نسخة أصلية لا تُعدل.
- إنشاء نسخة عرض Preview.
- إنشاء Thumbnail للصور والـPDF.
- تسجيل المستخدم ووقت الرفع.
- دعم OCR لاحقًا للملفات المصورة.

### 7.3 منطق الحفظ

```text
Original File = محفوظ ولا يستبدل
Preview File = للعرض
OCR Text = قابل لإعادة البناء
Metadata = قابل للتعديل وفق الصلاحية
Audit Log = غير قابل للحذف
```

## 8. دورة حياة الوثيقة

```text
استلام
→ إدخال أولي
→ استكمال البيانات
→ رفع الملف
→ تصنيف
→ مراجعة
→ اعتماد
→ إتاحة
→ حفظ طويل الأجل
→ أرشفة نهائية
```

| الحالة | المعنى |
|---|---|
| Draft | مسودة. |
| Pending Metadata | ناقصة بيانات. |
| In Review | قيد المراجعة. |
| Returned | معادة للتصحيح. |
| Approved | معتمدة. |
| Restricted | مقيدة. |
| Quarantined | محجورة. |
| Published Internal | متاحة داخليًا. |
| Published Public | منشورة للعامة — اختياري. |
| Archived | محفوظة نهائيًا. |
| Superseded | استبدلت بنسخة أحدث. |

## 9. سير العمل Workflow

### 9.1 إدخال وثيقة

```text
الموظف يضيف الوثيقة
→ يرفع الملف
→ يملأ البيانات
→ يرسل للمراجعة
→ المراجع يدقق
→ المدير يعتمد
→ الوثيقة تصبح قابلة للبحث حسب الصلاحيات
```

### 9.2 التصحيح

```text
المراجع يعيد الوثيقة
→ الموظف يصحح البيانات
→ يعيد الإرسال
→ المراجع يعتمد أو يعيد مرة أخرى
```

### 9.3 التقييد أو الحجر

```text
اكتشاف حساسية
→ وضع الوثيقة Restricted أو Quarantined
→ تحديد السبب
→ تحديد من يستطيع الوصول
→ تسجيل الحدث في Audit Log
```

## 14. متطلبات الأمان
